# Phase 5.3I-8.6 — Secure Evidence Intake Adapter

Date: 2026-11-21
Status: Implementation committed; runtime tests not executed; not yet connected to GitHub Actions certification workflows.

## Implemented

- `paper_a_replay_evidence_intake.py`: validates manifest structure/semantics without trusting producer statuses, then verifies every listed input/artifact hash using workspace containment and symlink rejection. It returns `PASS` or `FAIL` for intake checks only, echoes producer check records as claims, and explicitly labels certification `NOT_PERFORMED`.
- `test_paper_a_replay_evidence_intake.py`: tests successful intake with exact_values metadata, modified-file hash mismatch, workspace escape, symlink rejection (conditional), and missing artifact.
- README updated with scope and limitations.

## Independent check behavior

- Workspace root is resolved before intake.
- Manifest file is required to be inside workspace and regular.
- Manifest structural validation runs before file checks.
- Inputs and artifacts are checked separately; each is resolved with safe path helper and hashed.
- Producer PASS statuses are reported only as claims; they do not influence intake status.
- exact_values is retained and validated by manifest validator but its scientific interpretation is not checked.
- Any file-check error results in intake FAIL.

## Limitations / remaining work

1. These tests have not been run in this environment or CI.
2. Path checks remain vulnerable to concurrent filesystem races (TOCTOU); robust intake should use isolated extraction and descriptor-relative no-follow opens or equivalent.
3. Manifest file read itself currently resolves/contains the path and checks regular-file status but does not reject a symlink whose resolved target remains inside workspace.
4. No detached signature validation or trusted provenance.
5. No mathematical certification, numerical-claim validation, or certification workflow integration.
6. The existing Constant Llpoy Paper A pipeline/workflows were reviewed as the target integration surface, but no workflow was modified or dispatched in this step.

## Next

Perform source-level review and implement a race-resistant intake strategy (prefer isolated immutable bundle staging and no-follow descriptor operations where supported), then run the test suite in CI. Only after passing and review should the adapter be wired into existing verification workflows.
