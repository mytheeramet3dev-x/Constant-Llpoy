# Phase 5.3I-8.6/8.7 — Secure Evidence Intake & Race-Reduced File Handling

Date: 2026-11-21
Status: Adapter updated and CI workflow added; tests await an actual GitHub Actions run.

## 8.6 Initial intake implementation

- Manifest structure and semantics are checked without trusting producer check statuses.
- Input/artifact SHA-256 values are independently recomputed.
- Output separates producer claims from independent file checks and labels certification `NOT_PERFORMED`.
- Tests cover pass, hash mismatch, workspace escape, symlink, and missing artifact.

## 8.7 Hardening changes

- Intake now accepts only workspace-relative paths; absolute and parent-traversal paths are rejected.
- Workspace root is opened as a directory file descriptor.
- Each path component is traversed with descriptor-relative `os.open`; `O_NOFOLLOW` is used when supported by the platform.
- Final target is checked with `fstat` for regular-file type.
- Manifest is read through the same descriptor-relative safe-open method, so manifest symlink paths are rejected.
- File hashing reads from the opened descriptor, reducing path substitution races compared with resolve-then-open.
- Tests expanded for absolute path, traversal, manifest symlink, symlinked evidence, changed bytes, missing file, and successful intake with exact_values metadata.
- Dedicated GitHub Actions workflow added: `.github/workflows/paper-a-replay-evidence-intake-tests.yml`, triggered by changes in this package, pull requests, and manual dispatch.

## Security scope / residual risks

This is race-reduced file handling, not a complete sandbox or filesystem attestation. It depends on platform support and semantics for `O_NOFOLLOW` and directory-relative open operations. The workspace root and parent path setup remain trusted; mount changes, privileged actors, and broader filesystem adversaries are outside the stated guarantee. There is still no signature verification, claim-specific math verification, or certification.
